# arXiv Source Submission

This workflow creates a minimal, reviewable source archive for arXiv.
The guidance below was checked against the official arXiv documentation on 2026-10-13.
Recheck the linked pages before a final submission because arXiv changes its compiler and upload service over time.

## One-command workflow

Prepare a final manuscript, then run:

```bash
make arxiv
```

The command runs the submission checks, builds the manuscript with recorder output enabled, creates `output/arxiv/manuscript-arxiv.zip`, extracts that archive into a new temporary directory, and compiles it again from the archive root.
It clears any prior ZIP and reports before the submission checks, so a failed run cannot leave a stale candidate under the canonical upload name.
It renders both local PDFs with Ghostscript and requires every page to match pixel for pixel, which detects source-sanitization changes that compilation alone cannot reveal.
It also writes a human-readable inventory and SHA-256 checksum beside the ZIP.
The archive itself contains no inventory, build log, repository metadata, or workflow documentation.

The local isolated compilation is a strong preflight check, but it is not identical to arXiv's service.
Upload the ZIP, select `main.tex` as the only top-level file, select PDFLaTeX, inspect the complete processing log, and review the PDF generated by arXiv before completing the submission.

The generic template intentionally retains draft sentinels and unresolved section prompts.
CI therefore exercises the lower-level packager as a TeX Live 2025 smoke test without publishing its ZIP as an artifact.
This job runs independently of the TeX Live 2026 PDF builds, with its own checkout and regenerated artifacts.
Run the same checks locally with `make arxiv-check`.
This command compiles a reference-label specimen and verifies section, equation, figure, table, theorem, and shared-counter lemma types before testing packaging.
`make arxiv` delegates to the Python entry point's strict default path, which runs the submission gate before creating a candidate upload.
The explicit `--smoke-test` mode validates in temporary storage and never publishes an upload-named archive.
The isolated build must exit successfully and produce a final LaTeX log without unresolved citations, references, or fatal errors.
The ordinary manuscript, design-preview, and standalone-section build targets check their final logs too.
Standalone sections append a bibliography only when they cite sources.
Cross-section references still require their targets to be available in the standalone build; include or import the required reference context rather than suppressing unresolved-reference warnings.
Temporary warnings from earlier compilation passes do not invalidate a successfully resolved final pass.

The optional `--check` mode executes TeX from an existing ZIP and is only for archives produced from trusted project source.
Do not use it to inspect an untrusted download; use a disposable container or virtual machine for that task.
The checker limits compressed and extracted size and applies a compilation timeout, but these controls are not a security sandbox.

## Why the package uses an allowlist

The package is assembled from the actual local inputs recorded in `build/main.fls` after a fresh build.
Each dependency must also fall under an allowed path in `project/submission/arxiv.json`.
This two-part rule includes files that the manuscript actually reads while preventing a newly added repository folder from entering an upload by accident.

The default allowed paths cover:

- `main.tex`;
- manuscript setup and section files;
- the supplement;
- final generated figures and tables; and
- explicitly selected venue files.

The dependency record prevents unused files under those paths from entering the archive.
For example, `paper/setup/draft-commands.tex` is loaded only in draft mode and therefore cannot enter a final recorder-derived package after `submission-check` requires final mode.
Add a new allowed root only when the manuscript must load a file outside the existing boundary.
Never allow the repository root or broad workflow areas such as `project/`, `research/`, or `tools/`.

Generated files that arXiv needs are declared separately.
The default configuration maps `build/main.bbl` to `main.bbl`, whose basename matches `main.tex`.
This keeps the archive deterministic and avoids exposing uncited or internal entries from `references.bib`.
Declare a generated `.ind`, `.gls`, or `.nls` file in the same way if the final manuscript consumes one.

## Adapting an existing paper's build paths

Keep the packaging configuration aligned with the output directory used by the paper's normal LaTeX build.
The template's `latexmkrc` uses `build/`, so its default `recorder` and generated bibliography source are `build/main.fls` and `build/main.bbl`.
For a paper that builds in the repository root, set `recorder` to `main.fls` and the bibliography's `generated_files[].source` to `main.bbl` in `project/submission/arxiv.json`.
Keep the archive destination as `main.bbl` in either case.
Update any local PDF links and CI artifact paths when changing the normal build directory.

An existing bibliography in another directory can affect LaTeX's file lookup even when the compiler receives an explicit output directory.
For example, a build directed to `build/` can still read the repository-root `main.bbl` and never produce `build/main.bbl`.
The packager checks the bibliography path against the fresh recorder inputs before assembling an archive.
If the paths disagree, it reports both the configured source and the bibliography inputs actually recorded, including when an unused file already exists at the configured path.
It does not substitute another bibliography or remove existing build outputs.

Resolve a mismatch by aligning the normal build and packaging paths, then rebuild and run `make arxiv-check`.
If intentionally switching output directories, inspect and move aside obsolete generated files from the old directory before rebuilding; preserve manuscript source and any manually maintained bibliography assets.
The isolated compilation and rendered-PDF comparison remain required after the path check succeeds.

## Included and excluded material

The default ZIP includes only recorded manuscript dependencies and declared generated files.
Typical payload files are `.tex`, a matching `.bbl`, project-local class or style files when unavoidable, and final PDF, PNG, or JPEG figures referenced by the manuscript.
PDFLaTeX requires figures to be in a supported final format because arXiv does not perform figure conversion during compilation.
Every recorder-derived input must be classified either as a TeX-language file whose comments are removed or as a final binary asset listed in `copy_extensions`.
Unknown extensions fail closed rather than being copied without review.

The workflow excludes the compiled manuscript PDF, `references.bib`, ordinary LaTeX auxiliary files, logs, caches, editable figure sources, unused figures, data, literature PDFs, notes, response letters, scripts, tests, CI files, Git metadata, and hidden files.
It rejects every `.bib` file by extension because this workflow deliberately ships the generated bibliography rather than the full citation database.
It rejects unsafe paths, symlinks, unexpected local dependencies, and file names that arXiv would rename or reject.
It also rejects hidden-source constructs and TeX `^^` character notation, which can encode a comment marker before ordinary tokenization.

The staged copies of configured TeX-language files are sanitized without changing the working files.
Human-readable LaTeX comments and their markers are removed while escaped percent signs and literal percent characters in verbatim content are preserved.
Inline comment line endings and the following line indentation are removed together so the staged source retains TeX's original tokenization.
The isolated rebuild is required after this transformation.

These checks are not a complete privacy audit of arbitrary TeX programs or binary assets.
An unused macro can contain private text, and a figure can contain hidden layers or identifying metadata.
Pixel equivalence does not inspect PDF metadata, hyperlink destinations, attachments, or HTML semantics.
Review every packaged source file, asset, and link before uploading; remove internal content from its source when the sanitizer cannot classify it safely.

Select the manuscript license in arXiv's submission interface.
The packager does not assign a manuscript license, synthesize a license notice, or copy the repository's license and contributor files into the archive by default.
Its `extra_files` list is empty unless authors explicitly configure additional files with a source, destination, and review purpose.
Repository licensing and the license selected for the manuscript remain separate decisions.
Review the rights and notice requirements of any source, figure, class, style, bibliography style, or font included in the upload.
Prefer packages already provided by arXiv's TeX Live installation.
When redistribution requires a separate notice, preserve it through a reviewed `extra_files` entry; selecting an arXiv license does not override those input-specific terms.
The packager copies explicitly reviewed extras verbatim rather than converting or assigning their licensing terms.

## arXiv compatibility notes

arXiv currently offers TeX Live 2025 as the default and TeX Live 2023 as an alternative.
This template targets PDFLaTeX.
The CI package check uses TeX Live 2025; a local installation with another release provides useful but incomplete evidence.
arXiv documents a 2025-08-03 snapshot for its TeX Live 2025 service.
The CI container uses the same annual release, not a verified copy of that exact snapshot or arXiv's processing service.
The packager trusts only the installed distribution tree, its generated system files, and the active top-level TeX configuration.
It rejects dependencies from `TEXMFLOCAL` and user TeX trees so a locally installed custom package cannot be mistaken for an arXiv dependency.

Section files use the `subfiles` class and therefore contain their own `\documentclass` lines.
The arXiv interface may list them as possible top-level files.
Select only `main.tex`.
Do not add a hand-written `00README.json` for a normal interactive submission; arXiv creates that record from choices made in its upload interface.

arXiv advises against `\today` because a later rebuild can change the displayed date.
The template retains `\today` as its authoring default.
The packager replaces the standard `\newcommand{\paperdate}{\today}` definition in staged source with a fixed English date, without editing `paper/setup/metadata.tex`.
The default is the local calendar date when packaging starts.
Use `make arxiv ARXIV_DATE=2026-10-13`, or pass `--submission-date YYYY-MM-DD` directly to the script, to select a release date explicitly.
Repeat packaging with the same date to reproduce the source ZIP from unchanged inputs.
The reference build receives `SOURCE_DATE_EPOCH` and `FORCE_SOURCE_DATE=1` for that date, stabilizing the rendered comparison across midnight and backdated releases.
An already explicit `\paperdate` value is preserved, even when `ARXIV_DATE` is supplied.
Other executable uses of `\today` fail with an instruction to use an explicit date; literal code examples are left intact.
Custom localized dates and other clock-dependent macros require author review and an explicit fixed value.
The submission check also rejects the template's exact title, author, email, repository, and keyword sentinels, including optional values that may not be visible in the rendered PDF.

arXiv may warn about unusually large images and submissions.
The configured 50 MB archive guard is a conservative local review threshold, not a statement of arXiv's current service limit.
Optimize final figures and follow the live submission interface when it reports a different limit.

## Reference names and HTML accessibility

arXiv documents incorrect `cleveref` theorem names under TeX Live 2025.
The template does not add unused theorem environments to the manuscript.
If a paper introduces a section-numbered theorem, apply the documented alias in its setup:

```tex
\newtheorem{theorem}{Theorem}[section]
\AddToHook{env/theorem/begin}{\crefalias{section}{theorem}}
```

Shared counters need environment-specific aliases too.
The tested example in `tools/tests/fixtures/tex-references.tex` includes a lemma sharing the theorem counter and checks that its alias does not leak to the next theorem.
Extend the specimen for the environments and counter relationships used by a paper, and inspect rendered names after changing classes or theorem packages.

Keep `\title`, `\author`, `\maketitle`, `\begin{abstract}`, and semantic section commands in manuscript source.
The preprint profile styles these standard structures without substituting visual-only front matter in section files.
For each meaningful image, add a concise description through `graphicx`:

```tex
\includegraphics[width=\linewidth,alt={Plain-text description of the image.}]{figure-file}
```

Replace the path and description with the actual figure and the scientific content it conveys.
Compile with the selected TeX Live release; older local `graphicx` versions may not support the alt-text option.
Semantic commands and alt text do not establish that a PDF is tagged or that HTML conversion succeeded.
The pipeline checks PDF compilation and reference types, not LaTeXML conversion.
Review arXiv's HTML output when available, including title, authors, abstract, section navigation, references, equations, tables, and image descriptions.

## Overleaf editor diagnostics

Overleaf's static checker can report an invalid document-class option when class selection uses macros.
The `%%begin novalidate` and `%%end novalidate` comments in `main.tex` suppress only that line in the editor.
They do not disable compiler errors, and the packager removes them with other comments.
Investigate an actual compilation failure rather than expanding the suppression block.
